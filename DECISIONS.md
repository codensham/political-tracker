# Decisions

Log of decisions not covered by the spec, plus the owner answers of 2026-11-04. Newest entries go at the bottom. Each entry: what was decided, why, and what it affects.

## Owner answers (2026-11-04)

- **D-001 MVP done** means every dataset in spec §5 has schema, collector or skill, tests, MCP tool, and sample data. Backfill is ongoing operation.
- **D-002 Claude-assisted skills are five, candidate passed as an argument.** `extract-quotes-tags`, `backfill`, `check-positions`, `find-evidence`, `tag-records`. No per-candidate skills.
- **D-003 Real data from the build** is committed. Judgment data is reviewed in the PR.
- **D-004 Tracked people** are major-party presidential nominees 2000–2024: Gore, Bush, Kerry, Obama, McCain, Romney, H. Clinton, Trump, Biden, Harris. VP nominees, third-party candidates and primary runners-up are out.
- **D-005 Scope stays presidential and limited.** No other offices as candidates. The schema stays open to them.
- **D-006 Candidate model v2.** `status` and `party` are removed. `candidacies` (office, year, party, result, FEC ID, source) replace them. Result values: `potential, declared, withdrew, nominee, won, lost`.
- **D-007 Trump** is no longer marked `nominee`. He has 2016 won, 2020 lost, 2024 won candidacies. Ineligibility for 2028 is not a data field.
- **D-008 Social accounts** are `social_accounts` on the candidate record. Bio entries live in `data/bio/<candidate-id>/`, one record per office or education entry, judgment tier.
- **D-009 Aliases.** A per-candidate `aliases` list in the config. Matching needs the full name or an alias. A bare surname never matches.
- **D-010 Trump FEC 2024 totals.** The record shows $29,133.95 in receipts. Investigation and fix are planned in BUILD_PLAN Phase 2. Likely cause: the candidate-level totals are not the principal committee's.
- **D-011 Executive actions folder** is `data/executive-actions/`, as the code uses. The spec is updated to match.
- **D-012 No donor-industry data.** OpenSecrets bulk data is non-commercial, which conflicts with CC BY. Outside spending comes from FEC Schedule E instead.
- **D-013 No corrections field.** Corrections update the source fields in place. Git history is the audit trail.
- **D-014 Outlets.** AP, NPR, NYT, WSJ, Washington Post, CNN, Fox News, The Hill, National Review, The Atlantic. Any without a working RSS feed is dropped and logged here.
- **D-015 Lean ratings.** Only a link to the rater (AllSides, Ad Fontes) and a check date are stored. The rating value is never stored.
- **D-016 Polling** is recorded by the Claude-assisted `find-evidence` skill from pollsters' own releases. No automated scraping. RealClearPolitics is not used.
- **D-017 Fact-checks are out of scope** for this build.
- **D-018 State-level records.** OpenStates is out of scope. Governor executive orders go through the skill or manual entry, and are listed as a known limitation if not done.
- **D-019 Disclosures.** House Clerk annual index (official tier). OGE Form 278e and Senate eFD through the skill (judgment tier).
- **D-020 Crosswalk.** `taxonomy/policy_area_crosswalk.json` maps Congress.gov policy areas to topic IDs. Crosswalk-derived tags have `tagged_by: crosswalk@1` and auto-merge. Changes to the mapping need review.
- **D-021 Skill count and layout.** Five skills, as in D-002, under `.claude/skills/`.
- **D-022 Schedules.** Official records daily. RSS daily as a batched PR on `collect/articles`. Polls and fact-checks have no schedule (skill, on demand).
- **D-023 Collector failures.** All collectors run. The PR holds whatever succeeded. The workflow fails at the end if any collector failed.
- **D-024 Link and quote checks in CI** apply only to new or changed records. A 404 blocks. 403, paywall or timeout is a warning. Unverifiable quotes are flagged for the reviewer.
- **D-025 Archiving** uses anonymous Wayback Save Page Now, rate-limited, with retries. A failed archive leaves `archive_url` null. The record stays valid.
- **D-026 User-Agent** is `political-tracker (+https://github.com/codensham/political-tracker)`, with no email.
- **D-027 Article extraction** is tracked with `extraction_status: pending | done | skipped`.
- **D-028 Media attention** is computed on query, not stored.
- **D-029 Scale.** One file per record and an in-memory index. SQLite is added only if startup exceeds 5 seconds.
- **D-030 Tooling.** ruff is a dev dependency and runs in CI. Python 3.12 in CI. Commit locally per phase. Ask before pushing or opening a PR.

## Build-time decisions

- **D-031 API keys.** Keys are in `.env` at the repo root, which is git-ignored. Variables: `FEC_API_KEY`, `CONGRESS_API_KEY`, `GOVINFO_API_KEY`. `CONGRESS_API_KEY` is the same api.data.gov key as `FEC_API_KEY`. `GOVINFO_API_KEY` is unused (Federal Register covers executive actions). Git worktrees don't carry `.env`, so it must be copied into the worktree. The loader reads the environment first, then `.env`.
- **D-032 Articles path.** Articles are stored at `data/articles/<candidate-id>/<id>.json`, not `data/articles/<yyyy>/<mm>/`. `record_path` in code is canonical. The spec is updated.
- **D-033 Non-candidate records** use the first candidate ID's folder (as in `record_path`).
- **D-034 Outlet lean ratings** are stored as link and check date only, per D-015. The spec's `outlets/` folder is not created in this build; outlet config lives in `config/outlets.yaml`.
- **D-035 Executive-action presidents.** Presidents who held office (Bush, Obama, Trump, Biden) get Federal Register records. Their Federal Register president slugs are confirmed against the API during build. Gore, Kerry, McCain, Romney, Clinton and Harris held no executive office, so they have no executive-action records.
- **D-036 Votes and bills** carry `policy_area` (Congress.gov) as an optional field, next to `topics`.
- **D-037 Statements** must have `speaker` equal to the candidate's name or alias. The validator enforces it.
- **D-038 Trump FEC 2024 investigation** result is recorded here when Phase 2 is done.

- **D-039 verify script** runs ruff check, ruff format check, pytest, and `tracker.validate data`. The planned `pip install -e .` dry check is dropped: pytest already imports the editable install, so a broken package fails the tests.
- **D-040 Lint and format baseline.** Phase 0 added ruff. Existing code was auto-fixed (import order, unused imports, B007 loop variable rename) and reformatted. Behavior is unchanged; 76 pre-existing tests still pass.
- **D-041 API key redaction.** httpx error messages embed the full request URL, including `api_key`. A live FEC key appeared in test output during Phase 1. `tracker.http` now redacts `api_key` from every HTTP error message before it is raised. Owner action: rotate the FEC key at api.data.gov, since it was printed to a transcript and terminal output.
- **D-042 Trump aliases.** Trump's aliases are "Donald J. Trump" and "Donald Trump". The bare surname is excluded (D-009).
- **D-038 Trump 2024 finance (investigated).** The $29,133.95 receipts is FEC's own total for committee C00867275 ("Donald J. Trump Republican Nominee Fund 2024", coverage 2024-01-01 to 2024-08-08). It is the only committee linked to candidate P80001571 for 2024 in the API. The collector is not misparsing. The main 2024 campaign committee is not linked to the candidate in the API, and I could not identify its ID. No fix applied. Owner action: confirm the main 2024 committee ID on fec.gov; the collector can then query it as an extra committee.
- **D-043 Joint FEC names.** FEC shows Obama (P80003338) and Romney (P80003353) under joint names with their running mates. The IDs are correct for the candidates' own filings. Noted in the inclusion reasons.
- **D-044 Unverified IDs.** ICPSR and bioguide IDs for the nine new nominees are left null. They were not checked against Voteview or Congress.gov, and I won't guess them. Phase 5 fills them from Voteview and Congress.gov.
- **D-045 Candidacy scope.** Only major-party nominee candidacies count (D-004). Biden's 2008 primary run, Harris's 2020 VP run, McCain's 2000 primary run and H. Clinton's 2008 primary run are not recorded.
- **D-046 Outside spending.** One record per candidate, FEC candidate ID, cycle, committee and direction (support or oppose), from FEC Schedule E by-candidate totals. Schedule E totals have no per-filing date, so `published_at` is the cycle end (`YYYY-12-31`). Cycles come from the candidate's candidacy years. Records use type `outside_spending` in the `finance/` folder, which is in the official tier (D-031 spec §4a).
- **D-047 Shared folders.** `load_records` filters by requested type, and the validator checks each folder once. Two record types can share a folder.
- **D-048 Executive actions.** Federal Register records for Bush (1367), Obama (1781), Trump (1450), Biden (1069), collected 2026-11-04. Each set holds executive orders, proclamations and memoranda. The collector covers only presidents who held office (D-035).
- **D-049 Bioguide and ICPSR IDs.** Filled for the eight nominees with congressional careers from Voteview's member file (HSall_members.csv): Gore, Kerry, Obama, McCain, Romney, H. Clinton, Biden, Harris. Bush and Trump have no congressional career, so both stay null. This replaces the unverified IDs noted in D-044.
- **D-050 Bill collection.** Sponsored and cosponsored bills come from Congress.gov member endpoints. The list responses include `policyArea`, so no per-bill detail calls are made. Amendments (no bill type) are skipped. One record per candidate per bill: `bill-<congress>-<type>-<number>-<candidate>`.
- **D-051 Crosswalk coverage.** `taxonomy/policy_area_crosswalk.json` lists the Congress.gov policy-area names as I know them. Any name found in the data but missing from the file gets no topics and is listed for review in the Phase 5 log.
- **D-052 Vote tagging.** A roll call takes the topics of the bill with the same congress and normalized bill number (`H.R.1` → `HR1`). Votes with no matching bill keep `topics: []`. This is `tagged_by: crosswalk@1`.
- **D-053 Crosswalk additions from live data.** Policy areas seen in the collected bills but missing from the crosswalk: Commemorations, Disasters, Leases, Independent regulatory commissions, Credit, Depletion allowances, Power resources, Busing (School integration), Automobile theft. Mapped as: Credit→economy, Depletion allowances→taxes, Power resources→labor, Busing→education and civil-rights, Automobile theft→criminal-justice. The rest map to no topics.
- **D-054 Outlet feeds.** Eight outlets kept: NPR, NYT, WSJ (World News feed; the Politics feed returned 403), CNN, Fox News, The Hill, National Review, The Atlantic. AP (403) and Washington Post (502) dropped. Feeds checked 2026-11-04. rater_links are empty: AllSides and Ad Fontes page URLs must be verified by hand before they go in (D-015), so none are guessed.
- **D-055 Archive gap (needs owner review).** web.archive.org returned no response from the build environment (HTTP 000 on the home page and on Save Page Now), so no article could be archived in this run. The first RSS run is therefore 9 articles with `archive_url: null`. Spec §4 says a record without an archive link is invalid; D-025 says a failed archive leaves the link null and the record valid. The two conflict. I kept D-025 so the feed data is usable. Owner decision needed: keep null-allowed, or make archive required and hold articles until archived. The scheduled run in GitHub Actions may reach web.archive.org; that run will archive new items (25 per run) and rewrite these records with their archive links.
- **D-056 The Hill feed.** The feed URL redirects (301). The RSS client now follows redirects.
- **D-057 House Clerk disclosures (Phase 11).** The collector reads the current-year House index zip (`{year}FD.zip`, XML rows) and matches filers only by the exact name First + Last + Suffix against each candidate's `disclosure_names`. No nominee in the tracked set has a current House filing, so `disclosure_names` is empty for all of them and the collector writes nothing yet; the path is tested with fixtures. Gore's House years predate the current index. Adding a name is a config change in `config/candidates.yaml`.
- **D-058 Startup and SQLite cache (Phase 12, D-029 triggered).** Measured on the real data set (80,170 JSON records) on this machine: loading the JSON directly took 5.7 to 6.3 s, and 4.7 s of that is reading the files. Under the 5 s rule in spec §6, a SQLite cache is added at `.cache/index.sqlite` (git-ignored, outside `data/`). The cache is rebuilt when a fingerprint of every `.json` path, size and mtime changes; the fingerprint walk takes about 0.16 s. JSON stays canonical. Measured: warm startup 1.15 s; cold start (builds the cache) 8.27 s. The cold figure is above 5 s, so a fresh clone or CI checkout pays it once. Known limit: a cold start in CI is not under 5 s. Owner may choose to ship the cache or accept the cold start.
